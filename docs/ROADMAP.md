# ArchForm 开发计划

> 这个文件是项目计划的唯一记录。每次开发前先看这里:做到哪一步了、下一步要做什么。做完一项,就把状态改掉。

## 这个工具是做什么的

一句话:**把画框图变成填表单。**

编辑左侧结构树(图 → 层 → 分组 → 模块 → 条目),画布自动排版;样式、配色统一;完全离线,双击就能用。

## 为什么做这个(背景)

国内架构师画分层架构图(总体架构、应用架构、数据架构、技术架构等)时,用 draw.io、Visio 这类画布工具很痛苦:

1. **分层图其实是"嵌套结构",不是自由画布**——画布工具要手工拉框、对齐、调间距,时间花在"摆"而不是"想"
2. **风格靠人自觉**——字号、颜色、命名不统一,评审时吵的是风格,不是架构
3. **改版是灾难**——方案改几轮,画布要重新排版;结构化数据改一个词,自动重排
4. **没法版本管理**——图存在 Visio/draw.io 文件里,不能像代码一样 diff、review、追溯
5. **内容锁死在文件里**——架构资产没法复用
6. **没有中文场景模板**——总体架构、数据中台、数仓分层这些高频场景,现成模板是空的

结论:分层架构图应该"填数据 → 自动排版 → 统一规范"。这就是本工具做的事。

### v0.7 连线配置体验 ✅ 已完成

- **配置在画布上做**:连线编辑从「全屏遮罩弹窗 + 两个全量下拉」改为**右侧浮层面板**,改连线时整张图始终可见;起点/终点是手柄按钮,点一下进点选态,直接在画布上点层填入(捕获阶段拦截,不触发节点选中)
- **边配边看**:改线型/说明/增删行都即时以草稿绘制在画布上(不写数据、不落盘);「保存」才写入 `connections`;「取消」/Esc 丢弃草稿并回滚「在画布上显示」开关(此前的开关是即时生效且不可回滚)
- **智能默认**:「＋ 添加一条」的起点接上一条的终点、终点取它的下一层(连续画箭头不用反复选);「按层顺序自动连线」一键补满相邻层
- **配不出无效线**:横向流向下不相邻的层对在行内就地标黄提示,点选时就拦下,不会出现「保存后才弹一句警告、图上却没有」
- **多条连线不再重叠**:按「纵向区间是否相交」分配竖轨 —— 相邻层的链式连线首尾相接,共用**同一条对齐的竖轨**(一条竖线串到底,不会越往下越往左);只有区间真正重合的线(如 A→B 与 B→A)才往外让一条轨(左内边距随轨道数加宽),说明文字纵向等分错开;说明白底宽度按 Canvas 实测字形计算(不再是字数×11),中文不再被压线
- **可识别单条线**:每条线是独立 `<g>`,`overflow:hidden` 之外仍可 hover —— 移到线上加粗高亮、说明变深
- **保存即显示**:模板默认 `showConnections:false`,此前"加线 → 保存"后图上一条线都没有(数据写了、画布空白,看着像没生效)。现在开始加线/自动连线时自动勾上「在画布上显示」,保存时再兜底一次;想要"存着但不显示"手动取消勾选即可,取消面板仍按原值回滚
- **范围说明**:仍只做「层 → 层」。模块 → 模块连线需要布局反向让位(卡内挤线、跨层绕行会破坏"内容增删自动排版"),留待单独评估,详见下方「几条重要的设计约定」第 3 条

- **模板可自带配色**:模板数据新增 `scheme` 字段(取值同六套预置方案)。模板里的颜色仍统一按经典蓝色阶书写,加载时按档位映射到目标色阶 ⇒ 12 个模板不必都长成同一个蓝,新增模板也不用手算六档颜色。规则:从深链/开始页「创建」时套用模板配色;在编辑器内切换模板仍保留当前配色(不打断用户已选的方案)
- **12 个模板全部配好色与说明**:`desc`(一句话场景说明,≤40 字)+ `tags`(2~3 个场景标签)+ `scheme`。配色按场景分:入门/技术=经典蓝,总体/中台=灰蓝,应用/微服务=墨绿,数据/数据流转=紫罗兰,云平台/调用链路=青绿,安全/事件流=暖橙 —— 一眼能区分模板类型,不再 12 张一个色
- **开始页(启动面板)**:应用内浮层,讲清楚工具能做什么 + 快速开始(新建空图/从文本生成/导入 JSON)+ 12 个模板卡片。缩略图**用真实渲染器逐个渲染后缩放**,不是静态截图,改版式或配色后自动跟着变;首访(本机无存档)自动弹出,之后点工具栏左上角「开始」随时回到这一页,Esc/点遮罩关闭。缩略图渲染期间借用画布并在关闭时还原,不污染当前图
- **深链**:`?tpl=<模板key>` 以模板创建新图、`?preview=1` 直接进预览态、`?start=1` 直接打开开始页,便于书签/分享/嵌入与模板对比页
- **模板库(替代原「模板 ▾」下拉)**:顶栏「模板」打开模板库浮层 —— 搜索(标题/说明/标签/键名)+ 板式筛选(全部/纵向分层/横向流向)+ 场景标签(自动从各模板 `tags` 汇总,多了折叠成两行 + 「更多标签」)。缩略图与开始页共用同一套「真渲染一遍再缩放」的代码,并缓存成品,切换筛选不重渲染。模板涨到几十个也只是滚动 + 搜索,顶栏不再被下拉撑长;选中模板会先确认(当前有内容时),再套用该模板配色
- **模板校验**:`tools/check-templates.mjs`(零依赖)检查结构正确性 + 设计规范(元信息是否齐、层数 3~6、粒度上限),有 ERROR 退出码 1;12 个模板当前 0 ERROR / 0 WARN
- **接线检查**:`tools/check-html.mjs` 校验 JS 里 `getElementById` 的 id 在 `index.html` 里真实存在(运行期动态创建的走白名单),挡住"改 HTML 忘了同步脚本"这类低级错误
- **UI 冒烟测试**:`tests/ui-smoke.mjs` 用 Chrome headless + DevTools 协议真点一遍(开始页 → 选模板 → 配色套用 → Esc/遮罩关闭 → 新建空图 → 首访自动弹页),并兜住未捕获异常;零依赖,本地与 CI 同一套
- **CI**:`.github/workflows/ci.yml` 在 push / PR 时跑「语法检查 + 模板校验 + 接线检查」,再跑一个 Ubuntu 自带 Chrome 的 UI 冒烟 job

### v0.8.4 性能：点模板不再卡一下 ✅ 已完成

点「模板」/「开始」时，缩略图过去是**借真实画布**渲染的：每张先 `render()`（连结构树、缩放、连线一起渲染）再克隆 `.arch`，13 张就是 12 个 50~90ms 的长任务，首开能摸到近 1 秒的顿挫；重开面板还要把 13 份缩略图 HTML 重新解析一遍。

- **离屏渲染**：新增 `buildArchHtml()`，只产出 `.arch` 那一段 HTML；缩略图在格子里直接用这份 HTML，不再碰真实画布 —— 不渲染树/缩放/连线，也不会扰动用户正在编辑的那张图
- **配色不再动 `:root`**：`schemeDiagram()` 抽成纯函数，只改传入的模板对象；变量写在缩略图节点身上
- **一帧一张**：每张缩略图要排版一整幅 1600px 宽的真图（约 13ms），改成一帧只铺一张、铺完就让出主线程，面板打开后缩略图在 0.2~0.3 秒内逐张浮现
- **面板先亮、内容后铺**：`openTplLib` / `openStartPanel` 先把浮层显示出来，格子与缩略图放到下一帧建（`requestAnimationFrame`）
- **面板不再 `display:none`**：改成 `visibility:hidden`，关闭时保留布局，打开不必把 13 张真图重新排一遍（那一次约 100ms）
- **缓存按面板分开**：`thumbCache` 键为 `start|<key>` / `lib|<key>`，两个面板各留一份，避免互相搬节点把已画好的那一面搬空
- **实测**（headless Chrome，点下按钮到画面恢复的 rAF 最大间隔）：冷开模板库 **238ms → 30ms**、热开 **90ms → 35ms**、重开开始页 **112ms → 32ms**，长任务（>50ms）从 12 个降到 **0 个**

## 几条重要的设计约定

1. **连线不能破坏排版**。连线只走层与层之间预留的通道,图里的方块位置永远不变,内容增删时线自动跟着层走
2. **连线是可选项**。默认没有线,需要才打开;旧数据完全不受影响
3. **模块之间不画线**,用角标标注关系(如 `[调用:xx]`)。原因:卡片宽度由内容自动排版决定,模块级连线要跨卡片/跨分组绕行,一旦内容增删线就得重算路径,且线条必然压过卡片正文;层→层走的是层与层之间的固定通道,是唯一能长期稳定的粒度
4. **自由画线不在范围内**。需要复杂手绘时,用 draw.io 等画布工具;本工具可以导出 draw.io 格式,方便"结构在这里画,曲线去那边补"
5. **数据兼容**。所有文件带版本号,旧文件打开时自动升级;比工具更新的文件会给出友好提示,不会白屏或崩溃
