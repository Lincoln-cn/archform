# ArchForm(架构表单)开发版本规划

> 本文档是项目版本规划的**单一事实来源**。每个版本的开发开始前,先在此核对/更新对应条目状态(规划中 → 进行中 → 已完成),再实施。

## 一、项目定位

**ArchForm(架构表单)是一个"结构化框图"编辑器:把画框图变成填表单。**

与传统画布工具(draw.io / Visio / ProcessOn / 亿图)的本质区别:

- **结构化输入**:通过左侧结构树增删改 图 → 层 → 分组 → 模块 → 条目,画布自动排版
- **自动排版**:分层横向 / 中央核心 / 卡片网格三种板式,同一份内容一键切换,数据不丢失
- **规范固化**:样式规范(虚线面板、圆角 2px、字号层级)、六档配色方案随图保存,导出即评审稿
- **零依赖、完全离线**:单 HTML + 若干 JS,`file://` 双击即用,导出 SVG/PNG/独立 HTML 均无需网络

## 二、痛点背景

国内架构师绘制分层架构图(总体架构、应用架构、数据架构、技术架构等)时,成熟软件存在以下痛点:

1. **结构化框图 ≠ 自由画布**:分层架构图 90% 是"层→分组→模块→条目"的嵌套结构,画布工具强迫手工拉框、对齐、调间距,精力花在"摆"而不是"想"
2. **规范一致性靠人肉**:字号、颜色、虚线框、命名规范没有工具承载,评审会争吵风格而非架构
3. **改版是灾难**:方案评审改 N 轮,画布工具每改一处需重排;结构化数据改一个词自动重排
4. **版本管理缺失**:Visio 二进制、draw.io XML 无法 diff;架构图应像代码一样可 review、可 diff、可追溯
5. **内容锁死在画布里**:架构资产应进文档、进架构资产库、可复用
6. **中文场景模板空白**:总体架构、等保 2.0、云平台、数据中台、微服务、数仓分层等高频场景模板缺失

**结论**:分层架构图的正解是"数据 + 自动排版 + 规范固化"。ArchForm 用 3 个板式、统一数据模型、可选配色方案验证了这条路径。

## 三、版本规划

| 版本 | 目标 | 范围 | 状态 |
|---|---|---|---|
| **v0.1** | 编辑器核心可用 | 三种板式(layered/cards/central)、结构树编辑、属性面板、6 套配色 + 自定义、图例/右侧体系通栏、JSON 导入导出、localStorage 自动保存、导出 PNG(依赖 html2canvas) | ✅ 已完成 |
| **v0.2** | P0 基建:弹药与工程化 | 模板库四件套(总体/应用/数据/技术架构)+ 通用分层;离线 SVG 导出与 SVG→PNG(移除 html2canvas,全链路零网络);数据版本化 `schemaVersion` + `migrateDiagram` 迁移/兜底;开源起步(仅 GitHub, Apache-2.0)与 docs 文档目录 | ✅ 已完成 |
| **v0.3** | 结构化增强 | undo/redo;Excel/CSV 粘贴批量生成层与模块;连线(可配置、不强制:板式内生自动连线 + 层间 gutter 显式连线,仅层↔层)+ 模块关系角标标签;导出 draw.io XML 逃生通道;统计字段自动计算;JSON Schema + CI 模板校验 | 📋 规划中 |
| **v1.0** | 协作与生态 | 模板仓库化 + 预览图自动生成;网页版部署(GitHub Pages,保留 file:// 直开);团队规范包(配色/字号/命名规范一键套用);首个对外 Release | 📋 规划中 |

## 四、模板路线

1. **第一批(已落地)**:通用分层架构 + 系统总体架构 / 应用架构 / 数据架构 / 技术架构 四件套
2. **第二批**:中台架构(业务/数据/技术中台)、云平台架构、微服务架构、安全架构(等保 2.0)
3. **第三批**:卡片网格清单类(能力清单、服务目录、指标字典)
4. **社区化**:模板为纯数据,贡献者按 `templates.js` 结构新增即完成贡献;远期模板仓库化 + CI 校验

## 五、开源说明

- **平台**:仅 GitHub(仓库名 `archform`)
- **许可**:Apache-2.0(代码与模板数据同许可)
- **卖点**:零依赖、`file://` 直开、模板即数据(改 JSON 即可贡献)
- **贡献方式**:提 issue(模板请求 / 编辑器 bug)或 PR(新增模板 / 修复功能)

## 六、设计边界

**连线策略——规避而非硬扛**:

- 铁律:**连线永不改变布局**。连线只走预留通道(层间 gutter),盒子位置永不变动,内容变化时线随层边界自动重排
- 连线是**图的可选配置**(`diagram.connections` 可缺失,模板可带可不带,不强制),图属性面板提供开关;未配置即完全不渲染,旧 JSON 零影响
- 仅两种形态:**板式内生自动连线**(layered 相邻层箭头 / central 核心↔四区,位置由板式几何推导)与**层间显式连线**(仅层↔层,不做模块↔模块自由连线)
- 模块间关系不用线,用模块条目**角标标签**表达([调用:XX]/[依赖:YY])
- **逃生通道**:导出 draw.io XML,复杂图在本工具画结构、导到 draw.io 补自由线;自由曲线场景请使用画布工具

## 七、数据兼容承诺

- 所有图数据带 `schemaVersion`;旧数据(无版本号)视为 v1,加载时自动兜底
- 未来版本升级由 `migrateDiagram` 逐版本迁移,保证"任意版本的数据永远可打开"
- 版本过高(由更新版本创建)时给出友好提示而非崩溃
